  Qué era el bug

  Cuando el vendedor crea un cliente nuevo desde el POS (para asociarlo a una
  venta) y el backend rechaza el envío por validación (422) — por ejemplo,

  Estado actual — ya está arreglado

  Al revisar el código ahora mismo (Vendor/Index.tsx:773-786), setLocalErrors sí
  está activo:

  } catch (error: unknown) {

      if (axios.isAxiosError(error) && error.response?.data?.errors) {
          const errores = error.response.data.errors as Record<string,
  string[]>;
          setLocalErrors(
              Object.fromEntries(Object.entries(errores).map(([campo, mensajes])

● Confirmado, es exactamente eso. El bug es real y lo entiendo perfectamente.

  Causa raíz

  En Vendor/Index.tsx hay dos listas de clientes separadas, cargadas cada una de
  un endpoint distinto y ambas solo una vez, al montar la página (línea
  281-282):

  - clientes (cargarClientes → ventas.getClientes) — todos los clientes, usado
    en el selector principal "Cliente" de la venta.
  - clientesFisicos (cargarClientesFisicos → ventas.getClientesFisicosParaPago)
    — solo clientes tipo fisico, es la lista que usa el Combobox "Destino del 
    Pago" dentro de PaymentForm.tsx (la que usa el dueño cuando marca a un
    cliente como destino de un pago en USD).

  Cuando el vendedor crea un cliente nuevo desde el modal "Crear Nuevo Cliente"
  (línea ~761), el código solo hace:

  setClientes((prev) => [...prev, cliente]);

  Actualiza la primera lista, pero nunca toca clientesFisicos ni vuelve a llamar
  cargarClientesFisicos(). Por eso el cliente recién creado no aparece como
  destino de pago hasta refrescar la página (que vuelve a disparar el useEffect
  de montaje y recarga ambas listas desde el servidor).

  El fix

  Es un cambio de una línea, en el mismo bloque donde ya está setClientes(...)
  (~línea 761 de Vendor/Index.tsx):

  setClientes((prev) => [...prev, cliente]);
  if (cliente.tipo_cliente === 'fisico') {
      setClientesFisicos((prev) => [...prev, cliente]);
  }

  Nota: clientesFisicos en el frontend solo necesita { id, nombre_cliente }
  (interfaz ClienteFisico), y el objeto cliente que devuelve
  storeClienteForVenta ya trae esos campos (es el modelo completo de
  Cliente::create()), así que no hace falta un fetch adicional — con actualizar
  el estado local alcanza. Solo hay que filtrar por tipo_cliente === 'fisico'
  porque esa es la única condición que aplica getClientesFisicosParaPago() en el
  backend.

  ¿Aplico el cambio?
